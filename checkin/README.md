# Онлайн-регистрация гостя (электронная карта гостя)

Модуль «Анкета + договор найма с подписанием в 1 клик» по ТЗ «Модуль онлайн-чекина».
Гостю отправляется персональная ссылка `https://park-sever.ru/checkin/<токен>`, он заполняет анкету
и подписывает договор простой электронной подписью (ПЭП). Администратор видит всё в кабинете `/checkin/admin`.

Стек: **PHP 8.1+ и SQLite**, без фреймворков и composer — работает на любом российском хостинге
(Reg.ru, Beget, TimeWeb). PDF — tFPDF (LGPL, лежит в `lib/`), шрифт DejaVu Serif (кириллица).

## Сценарий

1. **Администратор** → «Новый заезд»: дом, заезд (по умолчанию 17:00), выезд (12:00), сумма, депозит 5 000 ₽.
   Система выдаёт уникальную ссылку и кнопки WhatsApp / Telegram / ВКонтакте / «Текст для MAX» / «Скопировать».
2. **Гость** открывает ссылку со смартфона → 4 шага:
   1. Анкета Арендатора: ФИО, дата рождения, паспорт (серия, номер, кем выдан, дата, код подразделения), адрес регистрации, телефон, email, автомобиль.
   2. Второй гость (по желанию): ФИО, дата рождения, документ.
   3. Договор найма (скролл-блок), Приложение № 1 — опись имущества дома с дефектами, Приложение № 2 — правила безопасности фермы в рамке, согласие на обработку ПДн.
   4. Сводка данных + обязательные галочки (кнопка «Подписать» неактивна без них) → «Подписать договор найма и подтвердить регистрацию».
3. **Сервер** в момент подписи фиксирует доказательства (см. ниже), формирует PDF, шлёт уведомление в Telegram.
4. Гость видит «Спасибо! … Гаечка, Рыжуля и Бэлла готовы встречать 🐾» и может скачать PDF-копию.
5. **Изменение условий:** админ меняет дом/даты/сумму в карточке — ссылка гостя сразу показывает новые данные.
   Если договор уже подписан, прежний PDF остаётся в архиве, а гость переподписывает новую редакцию по той же ссылке
   (анкета подставляется автоматически).
6. **Продление:** кнопка «Продлить проживание» → новая дата выезда + доплата → гость по той же ссылке
   подписывает дополнительное соглашение в 1 клик (отдельный PDF).
7. **Журнал заездов** со статусами: «Ссылка создана», «Ссылка отправлена», «Договор подписан», «Гость проживает», «Выезд оформлен», «Отменено».

## Что фиксируется при подписании (доказательная база)

| Что | Где хранится |
|---|---|
| Дата и время с микросекундами (UTC + МСК) | БД, PDF, журнал |
| IP-адрес (+ X-Forwarded-For), User-Agent, часовой пояс/экран/язык устройства | БД, PDF |
| Ключ ПЭП — уникальная ссылка (128 бит случайности), отправленная на телефон гостя | БД, PDF (начало токена) |
| Редакция текста договора и **SHA-256 текста оферты**, которую видел гость | БД, PDF |
| Дословные тексты проставленных галочек | БД (зашифр.), PDF |
| **SHA-256 итогового PDF** — любая правка файла задним числом обнаруживается | БД, журнал |
| **Журнал событий с хэш-цепочкой**: открыл ссылку, ошибки в анкете, подписал, скачал PDF… Каждая запись содержит хэш предыдущей — удалить или поменять запись незаметно нельзя | БД; последний хэш уходит в Telegram как внешний «якорь» |

Проверка целостности: `php cli.php verify` или страница «Журнал событий» в кабинете.

## Защита персональных данных (152-ФЗ)

- Паспортные данные в БД и PDF на диске **зашифрованы** (libsodium, ключ в `config.php`).
- База и PDF — в папке **вне сайта** (`data_dir`), на сервере в РФ.
- Ссылка не индексируется (`noindex`), не утекает через Referer (`no-referrer`), страница без внешних скриптов (строгий CSP).
- Кабинет: пароль (bcrypt), защита от перебора (8 попыток / 15 мин), CSRF, cookie `HttpOnly; SameSite=Strict`.
- Согласие на обработку ПДн — **отдельный документ и отдельная галочка** (с 01.09.2025 согласие нельзя «прятать» в договор).
- Telegram — иностранный сервис: по умолчанию в уведомление **не попадают ФИО и госномер** (`telegram_pii => false`).
  Формат из ТЗ с ФИО и авто включается `telegram_pii => true` — но сначала нужно уведомить Роскомнадзор о трансграничной передаче.

## Установка на хостинг

```bash
# 1. Залить папку checkin/ в корень сайта: .../www/park-sever.ru/checkin/
#    (деплой сайта из GitHub Actions её не трогает — стоит --exclude '/checkin/')
# 2. На сервере:
cd ~/www/park-sever.ru/checkin
cp config.sample.php config.php
php cli.php key          # вставить encryption_key и app_secret в config.php
php cli.php password     # вставить admin_password_hash в config.php
mkdir -p ~/checkin-data && chmod 700 ~/checkin-data   # и прописать путь в data_dir
```

- Нужен PHP 8.1+ с расширениями `pdo_sqlite`, `sodium`, `mbstring`, `curl` (на Reg.ru/Beget включены по умолчанию).
- Сайт должен работать по **HTTPS**.
- **Сделайте резервную копию `encryption_key`** отдельно от сервера: без него договоры не расшифровать.
- Бэкап данных — папка `data_dir` целиком. Хранить 5 лет.
- Telegram: создать бота у @BotFather, написать ему, узнать свой `chat_id` (например, через @userinfobot), вписать в config.

Локально: `php -S 127.0.0.1:4391 checkin/index.php` → http://127.0.0.1:4391/checkin/admin
(в `config.php` поставить `'public_url' => 'http://127.0.0.1:4391'`).

## Что нужно заполнить владельцу до запуска

- [ ] **Текст договора** (`app/documents.php`) — это проект на основе действующей оферты сайта, переписанный под
      найм жилого дома фермера (без «гостиничной» терминологии). **Обязательно вычитать юристом.** При правке — поднять `DOC_VERSION`.
- [ ] **Опись имущества** по каждому дому и суммы компенсации (`app/data/houses.php`). Сейчас суммы не указаны —
      печатается «по фактической стоимости восстановления». Для Дома № 1 внесён дефект «трещины на двух стеклопакетах кухни».
- [ ] Название второго дома.
- [ ] Реквизиты ИП (сейчас ИНН из раздела «Правовая информация»; ОГРНИП можно добавить в `LANDLORD` в `app/bootstrap.php`).

## Как это делают другие и что можно усилить позже

Онлайн-чекин в бронировании устроен похоже у всех: персональная ссылка из письма/мессенджера → анкета → согласие → подпись.
Отличаются способом идентификации:

- **Ссылка + паспортные данные** (сделано) — достаточно для ПЭП по 63-ФЗ, если это прописано в самом договоре (раздел 7).
- **+ SMS/звонок-код на телефон** — самый распространённый следующий шаг (так подписывают договоры сервисы электронной подписи
  и банки): код доказывает, что ссылку открыл владелец номера. Требует SMS-провайдера (SMS.ru, SMSC и т.п.) — легко добавить.
- **+ фото паспорта / селфи** — сильнее, но это уже больше персональных данных и строже требования к защите; для двух домов избыточно.

## Структура

```
checkin/
  index.php            точка входа (роутинг)
  cli.php              key | password | verify
  config.sample.php    образец настроек
  app/bootstrap.php    БД (SQLite), шифрование, журнал с хэш-цепочкой, хелперы
  app/documents.php    тексты: договор, приложения, согласие, доп. соглашение
  app/data/houses.php  дома и описи
  app/guest.php        экран гостя: проверка анкеты, подписание
  app/admin.php        кабинет
  app/pdf.php          генерация и шифрованное хранение PDF
  app/notify.php       Telegram
  app/views/           шаблоны (гость / кабинет)
  assets/              стили по канону сайта, JS, шрифты Lora и Monotype Corsiva
  lib/tfpdf/           библиотека PDF + шрифт DejaVu Serif
```
